# Правила комментирования кода Xatabchik

Источник правил — **уже существующие** docstring и `#`-комментарии в репозитории (`database.py`, `scheduler.py`, `platega_fulfillment.py`, `BanMiddleware`, `module_loader.py`, `callback_safety.py`). Этот файл фиксирует стиль. **В исходники комментарии не вносятся** (запрет на правку кода). Предлагаемый текст лежит в `docs/code_comments/`.

## Где что писать

| Место | Форма | Когда |
|-------|--------|--------|
| Файл | модульный `"""..."""` в первой строке | Файл с одной ответственностью (клиент API, fulfillment) |
| Функция / метод | `"""..."""` сразу после `def` / `async def` | Всегда: что делает; при необходимости — зачем и ограничения |
| Класс | `"""..."""` сразу после `class` | Назначение типа, не перечень методов |
| Неочевидный участок внутри функции | `#` на русском (как в `BanMiddleware`, `BotController`) | Только *почему*, не пересказ следующей строки |
| Константа / лимит | `#` рядом с присвоением | Единицы, CWE, магическое число (`MAX_MODULE_ZIP_BYTES`) |

## Текст docstring

1. Тройные двойные кавычки, сразу под сигнатурой, без пустой строки между `def` и `"""`.
2. **Первая строка** — одно предложение: что делает функция. В этом проекте чаще русский; английский оставляют охранным/legacy-хелперам (`fast_callback_answer`, CWE в ZIP).
3. Если нужны детали — пустая строка, затем абзацы: ограничения, крайние случаи, что *не* входит в ответственность, побочные эффекты (БД, HTTP, Telegram).
4. Не дублировать имя функции («Функция get_user получает пользователя»).
5. Не выдумывать типы, аргументы и исключения, которых нет в коде.
6. Не описывать каждую строку тела — только смысл и инварианты.
7. Примеры в docstring — только если без них неочевидно (даты, формат статуса, префиксы callback).
8. Секции `Args:` / `Returns:` в ядре почти не используются; не навязывать Google/NumPy-шаблон, если соседние функции файла его не используют.

Примеры стиля из кода (не менять формулировки в исходнике):

```python
def add_calendar_months(dt: datetime, months: int = 1) -> datetime:
    """Добавляет календарные месяцы к дате, корректно обрабатывая переполнение дней
    (например, 31 января + 1 месяц -> 28/29 февраля)."""

def should_account_lte_traffic(...):
    """LTE-учёт (снапшоты, baseline, энфорс) только при лимите и живом скваде.

    Безлимитный LTE (`lte_limit_bytes` 0/NULL) и хост без активного сквада класса
    `lte` не должны порождать запросы статистики на панель и строки в
    `key_lte_state` / `key_node_usage_snapshots`.
    """

def fast_callback_answer(arg):
    """Fast ACK for callback queries.

    This helper is intentionally *dual-mode* for backward compatibility:
    - As a decorator:  @fast_callback_answer
    - As an awaitable: await fast_callback_answer(callback)
    """
```

## Inline `#`

- Писать, если без комментария легко сломать инвариант (снятие `is_unreachable`, игнор внешнего `set_loop`, path jail).
- Не комментировать `i += 1` и очевидный `return None`.
- Язык — как у окружающего файла (в боте/БД — русский).

## Вложенные хендлеры

Большинство хендлеров объявлены *внутри* `get_user_router`, `get_admin_router`, `create_webhook_app`. Их комментируют так же, как модульные функции: одна строка «какой callback/маршрут и что делает», плюс блоки (проверка бана, запись pending, вызов панели).

## Что запрещено в этой задаче

- Любая правка `.py` / `.js` / HTML шаблонов.
- «Улучшение» уже существующего docstring в коде — в каталоге он **копируется дословно**.
- Домыслы: если поведение из кода не ясно, писать «по коду: …» и цитировать условие, а не додумывать бизнес-смысл.

# 🤖 Система защиты от ботов (Капча)

Функции: `data_manager/captcha_utils.py` (`generate_*`, `create_captcha_challenge`, `check_captcha_answer`, `has_passed_captcha`). Хендлеры: `bot/handlers.py` (FSM `Captcha`). Таблицы: `captcha_challenges`, `user_captcha_status`. Краткий гайд: [CAPTCHA_QUICK_GUIDE.md](CAPTCHA_QUICK_GUIDE.md).

## Обзор

Система капчи защищает бота от автоматических регистраций и поддельных аккаунтов. Она обязательна для прохождения новыми пользователями при первой регистрации.

## Особенности

✅ **Два типа капчи:**
- **Математическая** (вычисление простого примера: сложение, вычитание, умножение)
- **Кнопочная** (выбор правильного смайлика из предложенных вариантов)

✅ **Лимит попыток:** Пользователь имеет ограниченное количество попыток ввода ответа (по умолчанию 3)

✅ **Время истечения:** Капча имеет срок действия (по умолчанию 15 минут)

✅ **Данные о пройденных капчах:** Система ведёт историю пройденных капч для каждого пользователя

## Настройка

### 1. Включение/отключение капчи

Перейдите в **админ-панель → Система → Капча** и используйте переключатель **"Включить капчу"**.

### 2. Выбор типа капчи

В том же разделе выберите один из двух типов:
- `math` — математическая (по умолчанию)
- `button` — с выбором кнопки

```
Капча: [Математическая▼]
```

### 3. Максимальное количество попыток

```
Максимум попыток: [3        ]
```

Если пользователь исчерпает все попытки, ему будет предложено начать заново.

### 4. Время истечения (в минутах)

```
Timeout капчи (мин): [15       ]
```

После истечения времени пользователю нужно будет пройти капчу снова.

### 5. Кастомное сообщение к капче

```
Сообщение капчи:
[👤 Привет! Ты выглядишь как бот. Пройди простую капчу...]
```

## Технические детали

### Таблицы БД

#### `captcha_challenges`
Хранит информацию о капча-вызовах:

```
- id (PRIMARY KEY)
- user_id (ID пользователя Telegram)
- challenge_type (math/button)
- question (текст вопроса)
- correct_answer (правильный ответ)
- attempts (текущее количество попыток)
- max_attempts (максимум попыток)
- passed (прошла ли капча: 0/1)
- created_at (время создания)
- expired_at (время истечения)
```

#### `user_captcha_status`
Отслеживает, прошёл ли пользователь капчу при регистрации:

```
- user_id (PRIMARY KEY)
- passed_at (время прохождения)
- challenge_id (ссылка на последний вызов)
```

### API функции (captcha_utils.py)

```python
# Создание новой капчи
challenge = create_captcha_challenge(
    user_id=123456,
    challenge_type="math",  # или "button"
    timeout_minutes=15
)

# Проверка ответа
success, message = check_captcha_answer(
    challenge_id=1,
    user_answer="42"
)

# Получение активной капчи
challenge = get_active_captcha_challenge(user_id=123456)

# Проверка прохождения капчи
passed = has_passed_captcha(user_id=123456)

# Отметить капчу как пройденную
mark_user_passed_captcha(user_id=123456, challenge_id=1)
```

## Примеры использования в коде

### Для разработчиков

#### Пример 1: Создание капчи при регистрации

```python
from shop_bot.data_manager.captcha_utils import create_captcha_challenge

challenge = create_captcha_challenge(
    user_id=user_id,
    challenge_type="math",
    timeout_minutes=15
)

if challenge:
    await message.answer(
        f"Ответьте на вопрос:\n{challenge['question']}"
    )
```

#### Пример 2: Проверка ответа

```python
from shop_bot.data_manager.captcha_utils import check_captcha_answer, mark_user_passed_captcha

success, msg = check_captcha_answer(challenge_id, user_answer)

if success:
    mark_user_passed_captcha(user_id, challenge_id)
    await message.answer("✅ Капча пройдена!")
else:
    await message.answer(f"❌ {msg}")
```

#### Пример 3: Проверка перед доступом

```python
from shop_bot.data_manager.captcha_utils import has_passed_captcha

if not has_passed_captcha(user_id):
    await message.answer("Сначала пройдите капчу при регистрации.")
    return
```

## Поток регистрации с капчей

```
Пользователь написал /start
    ↓
Проверка: капча включена и пользователь новый?
    ↓ Да
Показать капчу (математическую или с кнопками)
    ↓
Пользователь отвечает
    ↓
Проверка ответа (макс. 3 попытки)
    ↓ Правильно
✅ Капча пройдена
    ↓
Продолжить обычную регистрацию
(проверка подписки на канал, согласие с условиями и т.д.)
    ↓ Неправильно и попытки есть
❌ Ошибка, осталось N попыток
    ↓ Попытки закончились
❌ Капча не пройдена, напишите /start
```

## Логирование

Все события капчи логируются в стандартные логи приложения:

```
[INFO] Created captcha challenge: challenge_id=123, user_id=456, type=math
[INFO] Captcha attempt: challenge_id=123, attempts=1/3, success=False
[INFO] Captcha passed: challenge_id=123, user_id=456
[ERROR] Failed to create captcha challenge: ... (причина ошибки)
```

## Безопасность

🔒 **Защиты:**
- Ограничение попыток (по умолчанию 3)
- Время истечения капчи (по умолчанию 15 минут)
- Хеширование не требуется (ответы хранятся в простом виде, т.к. это временные данные)
- Система работает на уровне БД и не требует внешних сервисов

⚠️ **Важно:**
- Капча срабатывает только при первой регистрации
- Повторно прошедший капчу пользователь не видит её снова
- История капч хранится в БД для аудита и анализа

## Отключение капчи

Если нужно временно отключить капчу:

1. Перейти в админ-панель
2. Раздел "Система → Капча"
3. Отключить переключатель "Включить капчу"
4. Сохранить

Новые пользователи смогут зарегистрироваться без капчи, но существующие проверки не удаляются.

## Часто задаваемые вопросы

**Q: Что если пользователь забыл ответ, пока писал?**
A: Капча имеет timeout (15 минут по умолчанию). После истечения нужно начать заново (/start).

**Q: Можно ли выключить капчу?**
A: Да, в админ-панели есть переключатель для отключения.

**Q: Как поменять тип капчи на лету?**
A: Измените настройку в админ-панели. Новые пользователи будут видеть новый тип.

**Q: Где хранятся данные о пройденных капчах?**
A: В таблицах БД `captcha_challenges` и `user_captcha_status`.

**Q: Как удалить историю капч?**
A: Через прямой доступ к БД (не рекомендуется для обычных пользователей).

# Лимит 300/мин на `/api/auth/check-token/{token}`: расчёт нагрузки

Решение владельца: **300 запросов в минуту на адрес клиента**. Корзина общая для всех токенов (PR #178),
`shared_limit("300/minute", scope="auth_check_token")`, константа `AUTH_CHECK_TOKEN_RATE_LIMIT` в `web_router/_core.py`.
Прежний лимит `30/minute` считался на каждый URL отдельно, то есть отдельно на каждый токен.

## Откуда берётся нагрузка

`login.html` (`startAuthPolling`) опрашивает адрес раз в 2 секунды, пока открыта вкладка с кнопкой входа через Telegram и вход не завершён:

- 1 вкладка: 60 / 2 = **30 запросов в минуту**.
- Лимит 300/мин на адрес: **10 одновременно ожидающих входа** с одного адреса (300 / 30), около 5 запросов в секунду на адрес.
- Прежний лимит 30/мин на токен: ровно один опрос в 2 секунды, без запаса (граничный случай, любая неточность таймера давала 429).

## Ёмкость по адресам

Ожидание входа обычно 10-60 секунд (перейти в Telegram, нажать Start, вернуться): 5-30 опросов на вход.

| Среднее ожидание | Опросов на вход | Входов в минуту с одного адреса (лимит 300) |
|---|---|---|
| 15 с | ~8 | 37 |
| 30 с | ~15 | 20 |
| 60 с | ~30 | 10 |

Одновременность важнее, чем частота: одиннадцатый одновременный вход с одного адреса частично получает 429. Клиент 429 не считает
ошибкой (`catch` и следующий опрос), поэтому вход не ломается, а задерживается до освобождения корзины (до минуты).

Адреса с высокой общей нагрузкой: мобильные операторы за CGNAT и офисы за NAT, где один внешний адрес у сотен пользователей. Вход через
Mini App внутри Telegram (`/api/auth/token` с `initData`) этот эндпоинт не использует, он нужен только для входа из обычного браузера.

Забытые вкладки: интервал не останавливается, пока вход не завершён. Одна забытая вкладка на экране входа занимает 30 из 300 запросов
в минуту этого адреса, пока браузер не заморозит неактивную вкладку (Chrome после нескольких минут замедляет таймеры до 1 раза в минуту).

## Нагрузка на сервер

Один опрос: проверка памяти, один запрос в БД по `auth_token`, один по `webapp_auth_requests` (SQLite), порядка 1-3 мс.
Даже 100 одновременно ожидающих входов это 50 запросов в секунду, это не нагрузка. Лимит нужен не для CPU, а чтобы один адрес не
гонял перебор. Перебор токена неосуществим: токен это UUID4 (122 бита).

## Если лимит придётся менять

Менять одну константу. Если нужно вернуться к меньшему значению (например 120/мин, 4 одновременных входа), сначала замедлить опрос на
клиенте до 3 секунд и останавливать его через 5 минут: это 20 запросов в минуту на вкладку и без забытых вкладок.

# Задача (низкий приоритет): `plan_id` в боте не сверяется с хостом при оплате

Статус: не начата. Код в рамках PR-0/PR-IP не менялся.

## Что найдено

- В `bot/user_router/payment_create.py` (строки около 63, 98, 192, 280, 379) `plan_id`
  берётся из данных FSM и ищется через `get_plan_by_id(plan_id)` без проверки, что тариф
  принадлежит выбранному хосту и активен.
- Хост и `plan_id` пользователь выбирает по кнопкам бота, а значения лежат в состоянии FSM,
  поэтому подмена возможна только через устаревшие или повторно нажатые кнопки, а не
  через произвольный запрос (в отличие от `/api/create-payment` до PR-0).
- При обработке платежа (`fulfillment.py`) тариф и хост тоже не сверяются.

## Что сделать

1. Общая функция «разрешить тариф для хоста» (как `_resolve_payment_target` в
   `webapp/web_router/payments_create.py`): тариф только из `get_active_plans_for_host(host)`.
2. Использовать её во всех ветках `bot/user_router/payment_create.py`.
3. Тесты: тариф другого хоста, неактивный тариф, неизвестный `plan_id`.
